## סקירה כללית

מערכת פתל היא מערכת ניהול תלמידים חיצוניים מבוססת אינטרנט הכוללת:
- **Backend:** ASP.NET Core Web API (.NET 9)
- **Frontend:** Vanilla JavaScript (SPA - Single Page Application)
- **Database:** PostgreSQL עם schema בשם `petel_schema`
- **Cloud Platform:** Microsoft Azure App Service

המערכת תומכת במבנה רב-ישויות (Multi-Entity) כאשר כל ישות (Entity) היא בית ספר או מועצה.

## תכונות אבטחה מיושמות

### ✅ 1. אימות משתמשים (Authentication)

#### 1.1 אימות דו-שלבי (Two-Factor Authentication - 2FA/OTP)
- **סטטוס:** מופעל במערכת (ניתן להגדרה בקובץ `appsettings.json`)
- **פרוטוקול:** Time-based One-Time Password (TOTP) תואם RFC 6238
- **ספרייה:** OtpNet
- **תהליך:**
  1. משתמש מזין שם משתמש וסיסמה
  2. אם `OtpEnabled=true` למשתמש, המערכת דורשת קוד OTP
  3. משתמש סורק QR Code באפליקציית Authenticator (Google Authenticator, Microsoft Authenticator)
  4. משתמש מזין קוד בן 6 ספרות
  5. המערכת מאמתת את הקוד מול Secret המאוחסן בבסיס הנתונים

**קבצים רלוונטיים:**
- `Controllers/OtpController.cs` - ניהול הגדרת OTP ואימות
- `Services/AuthService.cs` - לוגיקת אימות כוללת בדיקת OTP
- `Configuration/SecuritySetting.cs` - הגדרות אבטחה כוללות `OtpEnabled`

**הגדרות תצורה:**
```json
"Security": {
  "OtpEnabled": true,
  "OtpIssuer": "Petel External Students System"
}
```

#### 1.2 הצפנת סיסמאות (Password Hashing)
- **אלגוריתם:** BCrypt (BCrypt.Net-Next library)
- **Work Factor:** ברירת מחדל של BCrypt (מספר סבבי hashing)
- **אחסון:** `password_hash` בטבלת `users` - מאוחסן כ-hash בלבד, לא סיסמה בטקסט פשוט
- **אימות:** `BCrypt.Net.BCrypt.Verify(password, user.PasswordHash)`

**יישום:**
```csharp
// Services/AuthService.cs - שורה 74
if (!BCrypt.Net.BCrypt.Verify(loginRequest.Password, user.PasswordHash))
{
    return new LoginResponseDto { Success = false, Message = "שם משתמש או סיסמה שגויים" };
}
```

#### 1.3 ניהול סשן (Session Management)
- **אחסון:** In-Memory Dictionary (`ConcurrentDictionary<string, UserSession>`)
- **Session ID:** GUID ייחודי שנוצר בהתחברות
- **Token Storage:** Frontend מאחסן את ה-Token ב-`sessionStorage` בלבד
- **Timeout:** 24 שעות (ניתן להגדרה)
- **Cleanup:** Automatic cleanup כל 30 דקות להסרת sessions שפג תוקפם

**מבנה Session:**
```csharp
public class UserSession
{
    public string SessionId { get; set; }  // Token
    public string UserId { get; set; }
    public string Username { get; set; }
    public string UserFullName { get; set; }
    public string EntityId { get; set; }  // School/Council ID
    public string EntityName { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime LastAccessedAt { get; set; }
    public List<int> Roles { get; set; }
    public Dictionary<string, string> AdditionalData { get; set; }
}
```

**קובץ:** `Session/UserSessionService.cs`

### ✅ 2. הרשאות והגבלת גישה (Authorization)

#### 2.1 בקרת גישה מבוססת תפקידים (Role-Based Access Control - RBAC)
- **מודל:** Roles → Actions → Permissions
- **מבנה טבלאות:**
  - `roles` - תפקידים (מנהל, צופה, עורך וכו')
  - `system_actions` - פעולות במערכת (תפריטים, כפתורים, API endpoints)
  - `roles_actions` - קישור בין תפקידים לפעולות
  - `user_roles` - קישור בין משתמשים לתפקידים

#### 2.2 Action Authorization Service
- **אחסון בזיכרון:** Role-to-Actions mapping נטען לזיכרון בהפעלת השרת
- **ביצועים גבוהים:** בדיקת הרשאות ללא queries לבסיס נתונים
- **תמיכה בסוגי פעולות:**
  - `MENU_ITEM` - פריטי תפריט
  - `ONCLICK_BUTTON` - כפתורים בממשק
  - `PAGE_ACTION` - פעולות בדפים
  - `API_ENDPOINT` - קריאות API
  - `FILE_UPLOAD` - העלאת קבצים

**קובץ:** `Services/ActionAuthorizationService.cs`

**דוגמת שימוש:**
```csharp
// בדיקת הרשאה לפני ביצוע פעולה
var hasAccess = await _actionAuthService.VerifyOnclickAccessAsync(
    userId: int.Parse(session.UserId),
    screenName: "students",
    functionName: "deleteStudent"
);

if (!hasAccess)
{
    return Unauthorized(new { success = false, message = "אין הרשאה לפעולה זו" });
}
```

#### 2.3 Entity-Based Data Isolation (רב-ישויות)
- **עיקרון:** כל שאילתה לבסיס הנתונים מסוננת לפי `EntityId` של המשתמש
- **מניעת גישה לנתונים של ישויות אחרות**
- **יישום ב-BaseController:**

```csharp
protected UserSession? GetCurrentSession()
{
    var authHeader = Request.Headers["Authorization"].ToString();
    var token = authHeader?.Replace("Bearer ", "").Trim();
    return _userSessionService.GetUserSession(token);
}

// דוגמה: סינון נתונים לפי Entity
var students = await _context.Students
    .Where(s => s.EntityId == int.Parse(session.EntityId))
    .ToListAsync();
```

### ✅ 3. אבטחת תקשורת

#### 3.1 HTTPS Enforcement
- **סביבת ייצור:** Azure App Service מכפיף HTTPS אוטומטית
- **Middleware:** `app.UseHttpsRedirection()` ב-`Program.cs`
- **PostgreSQL:** חיבור מאובטח עם `SSL Mode=Require` בסביבת ייצור

**דוגמת Connection String (test environment):**
```json
"DefaultConnection": "Host=petel-test-db.postgres.database.azure.com;Database=petelappdb;Username=PetelAdmin;Password=PetelAdmin2025!;SSL Mode=Require;Trust Server Certificate=true"
```

#### 3.2 CORS Policy
- **הגדרת מקורות מורשים בלבד:**
```csharp
// Program.cs
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
    {
        policy.WithOrigins(
            "http://localhost:3000",  // Development
            "http://localhost:5173",  // Development (Vite)
            "https://petel-test-api-ahafcqfnh6drcdbd.israelcentral-01.azurewebsites.net",  // Test
            "https://petel.site"  // Production
        )
        .AllowAnyMethod()
        .AllowAnyHeader()
        .AllowCredentials();
    });
});
```

#### 3.3 Authorization Headers
- **כל קריאת API חייבת לכלול:** `Authorization: Bearer {token}`
- **אימות ב-Backend:** בדיקת Token מול UserSessionService
- **מניעת CSRF:** Session-based מול Token-based - המערכת משתמשת ב-Token בלבד

## ארכיטקטורת אבטחה

### Flow תהליך אימות והרשאה

```
┌─────────────┐
│   משתמש      │
└──────┬──────┘
       │ 1. Login (username, password, entityId)
       ▼
┌─────────────────────────┐
│  AuthController         │
│  /api/auth/login        │
└──────────┬──────────────┘
           │ 2. Validate credentials
           ▼
┌─────────────────────────┐
│  AuthService            │
│  - BCrypt verification  │
│  - OTP check (if enabled)│
└──────────┬──────────────┘
           │ 3. Create session
           ▼
┌─────────────────────────┐
│  UserSessionService     │
│  - Generate Token (GUID)│
│  - Store in memory      │
└──────────┬──────────────┘
           │ 4. Return Token
           ▼
┌─────────────┐
│   Frontend   │ Store in sessionStorage
└──────┬──────┘
       │ 5. API Request + Authorization: Bearer {token}
       ▼
┌─────────────────────────┐
│  BaseController         │
│  - Extract token        │
│  - GetCurrentSession()  │
└──────────┬──────────────┘
           │ 6. Validate session
           ▼
┌─────────────────────────┐
│  UserSessionService     │
│  - Check token exists   │
│  - Return UserSession   │
└──────────┬──────────────┘
           │ 7. Check permissions
           ▼
┌──────────────────────────┐
│ ActionAuthorizationService│
│ - Load user roles        │
│ - Check action access    │
└──────────┬───────────────┘
           │ 8. Grant/Deny
           ▼
┌─────────────────────────┐
│  AuditController        │
│  - Log attempt          │
│  - Record result        │
└─────────────────────────┘
```

## ⚠️ אזהרות אבטחה ופרצות פוטנציאליות

### 🔴 קריטי (Critical) - דורש תשומת לב מיידית

#### 1. **אין שימוש ב-JWT Tokens מאובטחים**
**תיאור הבעיה:**
- המערכת משתמשת ב-GUID פשוט כ-Token במקום JWT חתום
- אין אימות דיגיטלי של ה-Token
- ניתן לזייף Token אם יודעים את הפורמט

**השפעה:**
- תוקף יכול לנחש או לגנוב Token ולהתחזות למשתמש אחר
- אין expiration time אכיף ב-Token עצמו

**המלצה:**
```csharp
// להחליף את GUID ב-JWT מאובטח
using System.IdentityModel.Tokens.Jwt;
using Microsoft.IdentityModel.Tokens;

var tokenHandler = new JwtSecurityTokenHandler();
var key = Encoding.UTF8.GetBytes(_configuration["Jwt:Secret"]);
var tokenDescriptor = new SecurityTokenDescriptor
{
    Subject = new ClaimsIdentity(new[]
    {
        new Claim("userId", user.Id.ToString()),
        new Claim("entityId", user.EntityId.ToString())
    }),
    Expires = DateTime.UtcNow.AddHours(24),
    SigningCredentials = new SigningCredentials(
        new SymmetricSecurityKey(key),
        SecurityAlgorithms.HmacSha256Signature
    )
};
var token = tokenHandler.CreateToken(tokenDescriptor);
return tokenHandler.WriteToken(token);
```

#### 2. **סיסמאות בקובצי הגדרות**
**תיאור הבעיה:**
- `appsettings.json` מכיל סיסמאות בטקסט פשוט:
```json
"DefaultConnection": "Host=localhost;Database=PetelAppdb;Username=PetelAdmin;Password=PetelAdmin2025!"
```

**השפעה:**
- חשיפה של קובץ הגדרות = חשיפת גישה לבסיס הנתונים
- הסיסמה נמצאת בקוד מקור ב-Git repository

**המלצה:**
- שימוש ב-**Azure Key Vault** לאחסון סיסמאות
- שימוש ב-**Environment Variables** במקום קבצי הגדרות
- שימוש ב-**Managed Identity** לחיבור לבסיס נתונים ללא סיסמה

```csharp
// Program.cs
builder.Configuration.AddAzureKeyVault(
    new Uri($"https://{keyVaultName}.vault.azure.net/"),
    new DefaultAzureCredential()
);

// Connection string מ-Key Vault
var connectionString = builder.Configuration["ConnectionStrings:DefaultConnection"];
```

#### 3. **Session Storage ב-Memory בלבד**
**תיאור הבעיה:**
- Sessions מאוחסנים ב-`ConcurrentDictionary` בזיכרון השרת
- Restart של השרת = אובדן כל ה-Sessions
- לא מתאים ל-Scale Out (מספר שרתים)

**השפעה:**
- משתמשים יתנתקו בכל עדכון של האפליקציה
- לא ניתן להפעיל יותר מ-instance אחד (High Availability)

**המלצה:**
- שימוש ב-**Redis Cache** לאחסון Sessions מבוזר
```csharp
// Program.cs
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = builder.Configuration["Redis:ConnectionString"];
    options.InstanceName = "PetelApp_";
});
```

#### 4. **אין Rate Limiting**
**תיאור הבעיה:**
- אין הגבלה על מספר נסיונות התחברות
- תוקף יכול לבצע Brute Force Attack על סיסמאות

**השפעה:**
- אלפי נסיונות התחברות בשנייה
- ניחוש סיסמאות חלשות

**המלצה:**
- שימוש ב-**AspNetCoreRateLimit** library
```csharp
// Program.cs
builder.Services.AddMemoryCache();
builder.Services.Configure<IpRateLimitOptions>(options =>
{
    options.GeneralRules = new List<RateLimitRule>
    {
        new RateLimitRule
        {
            Endpoint = "POST:/api/auth/login",
            Limit = 5,
            Period = "1m"  // 5 attempts per minute
        }
    };
});
```

#### 5. **חוסר אימות Input Validation מקיף**
**תיאור הבעיה:**
- לא כל Controllers מבצעים אימות input מפורט
- חשיפה ל-**SQL Injection** דרך Entity Framework (נמוך, אך קיים)
- חשיפה ל-**XSS** (Cross-Site Scripting) בשדות טקסט

**המלצה:**
- שימוש ב-**Data Annotations** על כל DTOs
```csharp
public class LoginRequestDto
{
    [Required(ErrorMessage = "שם משתמש נדרש")]
    [StringLength(50, MinimumLength = 3)]
    public string Username { get; set; }

    [Required(ErrorMessage = "סיסמה נדרשת")]
    [StringLength(100, MinimumLength = 8)]
    public string Password { get; set; }
}
```
- הוספת **Input Sanitization** בממשק
- שימוש ב-**Parameterized Queries** (Entity Framework עושה זאת אוטומטית)

#### 7. **Hangfire Dashboard ללא הגנה מספקת**

- Hangfire Dashboard מוגן רק על ידי סביבת Development/Test

```csharp
// Program.cs
if (app.Environment.IsDevelopment() || app.Environment.EnvironmentName == "Test")
```

**המלצה:**

#### 8. **אין הצפנת נתונים רגישים בבסיס הנתונים**
**תיאור הבעיה:**
- שדות כמו `otp_secret`, `email`, `phone` מאוחסנים בטקסט פשוט
- במקרה של פריצה לבסיס נתונים - חשיפה מלאה

**המלצה:**
- הצפנת שדות רגישים ב-Application Level:
```csharp
public class User
{
    private string _otpSecret;

    [Column("otp_secret")]
    public string? OtpSecret
    {
        get => DecryptString(_otpSecret);
        set => _otpSecret = EncryptString(value);
    }
}
```

#### 9. **CORS מאפשר Credentials מכל מקור**
**תיאור הבעיה:**
```csharp
policy.AllowCredentials();
```
- בשילוב עם `WithOrigins()` - בסדר
- אך עדיף להגביל גם Headers ספציפיים

**המלצה:**
```csharp
policy.WithOrigins("https://petel.site")
      .WithHeaders("Authorization", "Content-Type")
      .WithMethods("GET", "POST", "PUT", "DELETE")
      .AllowCredentials();
```

```csharp
_logger.LogInformation("Login successful: {Username}, Token: {Token}", username, result.Token);
```
- Token מופיע בלוגים - חשיפה פוטנציאלית

**המלצה:**
- אל לכלול Tokens מלאים בלוגים
- Log רק חלק מה-Token או Hash שלו

#### 11. **אין Content Security Policy (CSP)**
**תיאור הבעיה:**
- Frontend לא מכיל CSP Headers
- חשיפה ל-XSS attacks

**המלצה:**
- הוספת CSP Headers ב-`Program.cs`:
```csharp
app.Use(async (context, next) =>
{
    context.Response.Headers.Add("Content-Security-Policy",
        "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'");
    await next();
});
```

#### 12. **אין X-Frame-Options**
**תיאור הבעיה:**
- האתר יכול להיטען ב-iframe - חשיפה ל-Clickjacking

**המלצה:**
```csharp
app.Use(async (context, next) =>
{
    context.Response.Headers.Add("X-Frame-Options", "DENY");
    context.Response.Headers.Add("X-Content-Type-Options", "nosniff");
    context.Response.Headers.Add("X-XSS-Protection", "1; mode=block");
    await next();
});
```

### הגדרות נוכחיות

**Deploy Script:** `Deploy-ToAzure.ps1`

#### ✅ תכונות אבטחה מיושמות:
1. **Environment-Specific Configurations** - קבצי הגדרה נפרדים לכל סביבה
2. **HTTPS Enforcement** - כל הסביבות דורשות HTTPS
3. **SSL/TLS לבסיס נתונים** - `SSL Mode=Require` בחיבור PostgreSQL
4. **Verification Steps** - בדיקות post-deployment למניעת שגיאות

#### ⚠️ חוסרים באבטחת Deployment:

1. **סיסמאות ב-Script**
   - Script מכיל שמות App Services וResource Groups
   - אין secrets management במהלך ה-deployment

2. **אין Backup לפני Deployment**
   - Deployment ישיר ללא snapshot של המצב הקודם

3. **אין Rollback Mechanism**
   - במקרה של כשל - צריך deployment ידני מחדש

**המלצות לשיפור Deployment:**

```powershell
# 1. Create backup before deployment
az webapp deployment slot create --resource-group $rg --name $appName --slot backup

# 2. Deploy to staging slot first
az webapp deployment source config-zip `
    --resource-group $rg `
    --name $appName `
    --slot staging `
    --src "deploy-$Environment.zip"

# 3. Run smoke tests
Invoke-WebRequest -Uri "https://$appName-staging.azurewebsites.net/api/health"

# 4. Swap to production only if tests pass
az webapp deployment slot swap `
    --resource-group $rg `
    --name $appName `
    --slot staging `
    --target-slot production
```
